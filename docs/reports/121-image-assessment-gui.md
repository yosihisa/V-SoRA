## 読者向け概要

画像を出力できたこと、数値計算が収束したこと、元の天体の形を正しく復元できたことは、それぞれ異なる。たとえば[119](119-fixed-field-image-grids.md)では、8格子の計算は収束したが、通常の周波数差推定を使った画像は、同じ格子の事前画像より正解に近いとはいえなかった。逆に、未収束だから画像の全情報が無意味だとも断定できない。結果を正しく読むには判定を分ける必要がある。

この段階は[109](109-image-path-acceptance.md)の既存評価APIを日本語GUIにつないだ。「処理の状態」「選択された探索」「参照画像との差」を並べて示す。参照画像がない実観測では「参照なし・未評価」と表示し、分からない画質を誤差0に置き換えない。画像復元の性能を改善する段階ではなく、主経路の結果を解釈するための機能である。

## 1. 目的・対象範囲

`rml`、`analysis`、`sequence`、`synthesis`の保存済み実行結果を読み取り時に評価する。原本`summary.json`、相関器、RML solver、探索設定、比較指標を変更しない。処理が終わったか、選ばれた初期値からの探索が停止条件に達したか、模擬正解との参照比較が有効かを分離する。原本のSHA256（内容から作る識別値）と評価JSONを保存できるようにする。

## 2. 完了条件

1. 実119由来の6種類の保存記録で、収束/未収束/参照なし/画像未実行/不正RML/旧参照を区別する。
2. 新しい対象試験と既存GUI・判定試験、source/導入済み両全回帰を完了し、除外0とする。
3. 両実Chromiumで全三カードの表示値・制約数・既存χ²、全評価JSONの実保存、実RMLと既存CLEANのフォーム実行、画像読込、日本語390pxを確認する。
4. リポジトリ外の作業フォルダでrunnerを使わず、導入元、wheel全ファイル、同梱データ、原本不変、依存関係を確認する。
5. レポート・索引・操作案内・形式説明、公開監査、匿名コミットとdevelopmentへのpushを完了する。

## 3. 実際に行った作業

- `apps/ui/src/vsora_ui/image_assessment.py`：既存`assess_rml_result`の呼出しと、処理状態・参照形式の対応。
- `server.py`：実行詳細に評価を付け、評価JSONの保存APIを追加。同じ読込bytesから原本の識別値を計算。
- `static/image-assessment.js`、`app.js`、`index.html`：三つの判定を日本語表示。旧参照の数値を現行の形状評価として二重表示しない。
- `apps/ui/tests/test_image_assessment_gui.py`：実記録、境界値、原本不変、JSON保存APIの22試験。
- `tools/verify_image_assessment_browser.py`：6記録と実workerを扱う、source/installed共通の実ブラウザ照合。
- [操作案内](../guide/06-gui.md)、[評価JSONの説明](../design/gui-image-assessment.md)、本レポート・索引・小容量の正式記録。

旧参照値や不正な参照値があっても、有効なRMLの収束記録は失わない。不正なRMLは「記録を確認できません」と表示する。CLEANと統計参照のジョブにRML評価を付けない。保存済み記録の診断であり、画像ファイルの存在を認証する機能ではない。

## 4. 検証条件・結果

新22を含む対象143試験が463.14秒で成功。既存警告9641件。全収集は両2116件、正式全回帰はsource 609.28秒・導入済み607.5秒で各2116成功・除外0、既存警告は各27396件。115以来の2055件を引用するだけでなく、116〜119の新試験と今回のGUIを含めて全件を再実行した。

### 実ブラウザ

段階119の通常LO枝の8格子（収束）・32格子（未収束）の実RML出力を使用した。参照なし・不正な選択run・旧形式は、この実記録から検証用に編集した条件である。失敗して画像がない条件も用意した。編集した記録を新しい観測実験の結果としては数えない。

source/installed各環境で、6条件すべての三カード表示とJSON保存を確認した。参照ありではNRMSE、画像ありでは独立phase/amplitude制約数と既存χ²を記録の数値から照合した。評価本体は新GUI helperを使わず、別processから109の公開APIを呼んだ結果と完全一致した。

さらに両GUIの既存フォームから4局・二点源・8時刻・観測全体600秒・0.3秒積分・初期値1個・反復上限100の実RMLを1件ずつ実行し、生成画像を読込み、評価JSONを保存した。この短い探索の収束を必須にせず、実際の停止結果をそのまま照合した。通常CLEANも4局・点源・600秒/60秒積分で実行し、画像2枚以上の読込とピーク約1000Jy/beamを確認した。これらは仮定モデルによる処理回帰で、実機観測ではない。

両方とも実Chromium 153.0.8010.12、実保存7件、sourceまたは導入先にある11 module、日本語font・390px幅、ページの横はみ出しなし、JSエラー0・外部通信0。workspaceはリポジトリ外で`tools/run.py`なし。source版は明示した開発ソースから、導入版は導入先からmoduleを読んだ。WindowsブラウザとWSLg desktopそのものの直接確認はしていない。

### 失敗と修正

- コピーGUIによる予備22試験・予備ブラウザは正式件数に加えなかった。
- 正式sourceブラウザの初回は、閉じた詳細設定の入力欄を操作して待ち時間切れになった。検証toolが詳細欄を開いてから操作するよう修正し、再実行した。アプリ本体・科学計算はこの修正で変更していない。
- 初回wheel構築は検証環境にsetuptoolsがなく失敗した。一時的な専用構築環境を使って作成し、実行用依存関係を追加変更せずに導入した。失敗ログもGit管理外に保存した。

- 既存のartifact移動を扱う2試験で、種類名`kind`を持たない古い履歴からKeyErrorが発生した。初回両全回帰は各2失敗であり、正式成功へ加算していない。実行中の回帰が両方終わった後、種類名がない記録は従来どおり開けるように修正した。ソース/試験/toolを再凍結し、対象143と両全2116、wheel導入と両実ブラウザを再実行した。

正式回帰中のソース・試験・tool等402ファイルのSHA不変を確認。wheel103ファイルと参照asset4件はsource・導入先・wheelでbyte一致、pip check成功。原本の保存済みsummaryは全条件で不変だった。公開監査指摘0、文書リンク1589件で欠落0。

小容量の機械可読記録と図は[正式記録](../../validation/runs/stage121/README.md)を参照する。実行ログ・ブラウザ全画面・wheelはGit管理外の`outputs/stage121-*`へ残す。

## 5. 制約・未解決事項

- NRMSEは参照との相対的な形の差で、天体の存在確率や画像の信頼確率ではない。閾値による新しい合否判定は追加していない。
- 旧参照形式を現在の全支持領域による評価へ変換しない。正解がない実観測は未評価である。
- 原本SHAは読んだ内容の対応を示すだけで、正しい観測入力であることを保証しない。構文自体が壊れたJSONの修復も対象外である。
- 実機Cas A、未知振幅/SEFD/弱い実信号のLO、低SNRの画像尤度、実FFTの独立性、全夜運用・GPU性能は未検証。既存RMLの高SNR近似はそのままである。
- 二点源・既知参照の回帰成功を、実RTL-SDR/OCXO観測の成功へ読み替えない。
