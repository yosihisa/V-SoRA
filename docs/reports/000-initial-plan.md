## 1. 目的・対象範囲

これまでの調査・設計と会話での判断をまとめ、以降の開発の基準を残す。ソフトウェアの実装、候補ソフトの導入・実行、観測性能の実証は今回の対象に含まれない。

## 2. 観測目標と確定条件

- OCXOをクロック源に用いる改造RTL-SDR受信機で観測網を構築する。
- 対象はCas A、観測周波数は1.42 GHz、最大基線長は約600 m。
- 各局のWindowsノートPCで収録し、Linuxマシンで相関・校正・画像復元・シミュレーションを行う構想。GPU利用は処理方式に応じて検討する。
- 観測信号の保存・交換形式はVDIF、visibilityの保存・交換形式はFITS-IDIを基本案とする。
- 文献調査、開発目的、作業内容、検証結果を同じリポジトリで管理し、開発段階ごとにコミットする。

局数、実際の局配置、アンテナ、感度、帯域、偏波、観測時間、同期方式、既存PCの仕様は未確定。

## 3. これまでの調査と設計判断

### 3.1 処理構成

```text
各局SDR → 時刻対応したIQ → VDIF＋観測メタデータ
       → 相関・遅延補正 → FITS-IDI → 校正・画像復元 → 画像
```

収録ソフトが最初からVDIFを出力する構成は可能。従来の設計文書にある未加工IQ/SigMFからLinuxでVDIFへ変換する構成は、時刻推定や再処理のための選択肢であり、必須ではない。直接VDIF保存＋付随メタデータも候補とし、時刻対応方式を設計してから採用案を確定する。

GPSDOの周波数基準、PPS、PPSとサンプル番号の対応は別の情報である。標準RTL-SDR APIからサンプル対応のハードウェア時刻が得られるとは扱わない。PCのUSB受信時刻を実サンプル取得時刻と混同しない。

### 3.2 VDIF以外に必要な情報

- アンテナ基準点の位置、座標系、測定誤差。
- 対象・位相中心の赤経赤緯と座標系。
- 観測区間、ファイル一覧、局ID・threadと受信チャンネルの対応。
- RF周波数、帯域、サンプルレート、周波数軸の向き、I/Q・量子化規約、偏波。
- 時計オフセットとドリフトの基準時刻、受信機・ケーブル等の遅延。
- チャンネル数、積分時間、基線・偏波積などの相関条件。
- 相関方式に応じた遅延モデルと地球姿勢情報。

PPS対応、時計ロック状態、欠落、設定変更、ゲイン等の収録ログも残す。感度や校正天体の情報は主に相関後の校正に利用する。共通JSON/YAMLからDiFX等の固有設定を生成する方針であり、独自JSONを既製相関器が直接読めるとは想定しない。

### 3.3 流用と自作

候補は [ソフト候補調査](../literature/2026-10-02-software-candidates-1420mhz.md) に34件整理済み。収録API、VDIF入出力、相関器、FITS-IDI、校正・画像化、シミュレーションに分けている。互換性や実行可能性は未検証。

自作の中心は観測設定、時刻対応と補正、データ品質記録、ソフト間変換、シミュレーター、実行管理と比較レポート。相関器・画像復元は既製ソフトを利用する選択肢を維持し、全面自作は確定していない。

### 3.4 容量・計算機の概算

以下は4局、単一偏波、2.048 MS/s、8 bit I＋8 bit Q、4時間という未確定の仮定に基づく。

- IQは約59 GB/局、4局で約236 GB。
- IQとVDIFを両方保持すると4局で約473 GB。
- 1024チャンネル・1秒積分・自己相関込みのvisibility要素は約1.92 GB。FITS-IDI/MSの実ファイル容量ではない。
- Linux作業SSD 1 TB、RAM 32 GB程度を初期検討枠としているが、実測した最低要件ではない。
- CPUを基準経路に置き、GPUは対応する処理を選んだ場合に利用する。

詳細と8局時の概算は [運用構成案](../design/2026-10-02-operational-architecture.md) に記載。短い積分時間ではvisibility容量が大幅に増える。時計・位相誤差を残したまま平均して失われた相関は、後処理だけで回復できるとは限らない。

## 4. Cas A参照画像の確認

読み取ったファイル：隣接プロジェクトの `VSP-VLBI/data/reference/VLA_lband_2017.fits`。同名ファイルが別プロジェクトの `vlbi/AntennaAensitivity/` にも存在するが、この段階では同一性を検証していない。公開文書にはユーザー名を含む絶対パスを記載しない。

FITSヘッダーの読み取り結果：

| 項目 | 内容 |
| --- | --- |
| 対象・装置 | CassiopeiaA・EVLA |
| 観測日時 | 2017-08-13T04:34:57.499999 |
| 画像 | 512×512、2秒角/画素 |
| ビーム | 約13.8×8.1秒角 |
| 輝度 | Jy/beam |
| 座標 | FK5、基準元期2000、RA/DECのWCSあり |

[CDS/VizieRカタログ](https://vizier.cfa.harvard.edu/viz-bin/VizieR?-source=J%2FA+A%2F612%2FA110) には1378 MHzと1750 MHzの連続波スペクトル窓を組み合わせた画像と記載されている。出典は [Arias et al. (2018)](https://doi.org/10.1051/0004-6361/201732411)。

付随ファイル `casa-vla-lband-2017.json` の1420 MHzはヘッダー欠落を補う仮定であり、観測周波数の確認値ではない。同ファイルに書かれたchecksum一致や総フラックスは過去の記録で、今回再計算していない。

この画像は天体モデルとして利用できる。取り込み時にJy/beamからJy/pixelへ変換し、背景、負の画素、対象範囲を確認する。元画像と加工モデルを分けて保持する。形状評価には有用だが、周波数差・経年変化を補正せず現在の1.42 GHzでの絶対フラックスとは扱わない。初期は形状を採用し、総フラックスを可変パラメーターとする。

公称分解能の目安は `λ/B ≈ 73秒角`（1.42 GHz、600 m）。実際の復元品質は短基線、uv被覆、感度、校正にも依存し、画像の存在だけで観測成功を保証しない。

## 5. 開発構想

| 段階案 | 目的・成果物 | 判断すること |
| --- | --- | --- |
| 001 | 共通設定・評価基準、参照画像の取り込み | 単位・座標・天体モデルと再現条件を定義できる |
| 002 | visibilityシミュレーターと画像復元の最小構成 | 理想条件で点源・2点源・殻状モデルを復元できる |
| 003 | Cas Aモデル、局配置・観測時間・雑音の比較 | 検出、大きさ、形状を復元できる条件の範囲 |
| 004 | IQシミュレーター、VDIF、相関器の接続 | 相関結果が独立に計算した参照visibilityと一致する |
| 005 | 時計・LO・位相・量子化・欠落の誤差モデル | 必要精度と補正可能な範囲 |
| 006 | 2受信機での短時間実機確認 | 実際の誤差を想定モデルで扱える |
| 007 | Windows収録フロントエンド | 必要なデータと時刻・品質情報を保存できる |

段階番号・範囲は実際の依頼に合わせて調整する。長時間の配置検討は軽いvisibility生成を基本にし、IQの確認は短時間から始める。参照値と処理系は独立した方法でも比較し、同じ誤りを双方に組み込むことを避ける。

最初の判断は「Cas Aを検出できる」「広がりを復元できる」「殻状の形を復元できる」を分ける。数値の合格基準は段階001で定義する。アンテナ感度が未確定なら複数の仮定で範囲を評価する。
