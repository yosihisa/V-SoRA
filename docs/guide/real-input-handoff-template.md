# 実入力と測定根拠の引渡し票

この票をコピーして観測記録へ記入する。[Linux入力確認表](../../interfaces/linux-input-readiness.md)にある要求を、原本と測定根拠へ対応付けるための人向け文書である。**manifest/clockのJSON schemaではなく、この票を読む新しいparserや自動判定機能もない。** 現parserへ任意の追加keyを挿入しない。

未記入の値を模擬例の値で埋めない。各値の状態は「実測」「推定」「供給・計算」「未測定/不明」を区別する。正しく読めること、同じbyteであること、物理的に正しいことは別々に記録する。機器や実記録を受け取っただけではCas A画像化の成功とは判定しない。

| 取得環境、実際に取得できたことを示す記録 | 未記入（USB一覧やツール名だけとは区別） |

装置serial、個人の連絡先、詳細な私的局住所、認証情報、ユーザー名入りpathは公開版へ書かない。必要な識別対応は非公開記録へ置き、公開版では一般化した局ID・根拠IDを使う。

| 公称sample rate | 未記入 | 未確認 | 未記入 | 未評価 | 未記入 |

sample0はUSB到着時刻で代用しない。公称rateを入力してheaderを解釈できたことを実rateの測定としない。模擬原本に供給した正確なclock/scaleや仮定SEFDを、実装置の測定根拠へ流用しない。

この票は、相対Closure＋RMLを使うために精密gain較正や絶対flux測定を一律に必須とするものではない。未測定を明記し、どの主張・誤差モデルに必要な情報が不足するかを区別する。未知SEFD等を仮定値で隠して、低SNR尤度やconfidenceの適用条件が成立したと扱わない。

## 3. 既存の入力へ対応付ける

| 既存の入力 | この票で対応させる情報 | 検査で保証しないこと |
| --- | --- | --- |
| [session manifest](../../interfaces/session-manifest.md) | 局/VDIFの対応、公称rate、FFT/積分、decoded scaleと単位 | scaleの物理較正、I/Qの向き、天体検出 |
| 観測設定 | UTC原点、RF中心、局位置、phase center | 収録時刻やアンテナ応答の実測精度 |
| [clock JSON](../../interfaces/clock-model.md) | sample0のoffset、実rate、通過帯域の根拠 | 数値型が正しいだけでは時計精度を証明しない |
| rate profile | 使用pilot・局順・時刻原点・有効区間・推定の成否 | 未知のalias、速い位相変動、同pilot依存や実機confidence |
| 元のinvalid/変更記録 | 欠損や一定設定の区間境界 | 穴を測定された0電圧へ置き換えない |

現在の受渡しprofileはEDV0・8bit complex・1channel・thread0、sessionは4096sample/frameである。これはリポジトリの対応範囲で、全VDIFや各装置のnative IQを無条件に読める意味ではない。対応形式への変換が必要なら、元IQを保持し、変換版・I/Q/時刻/scaleの対応を別に記録する。Windows収録や任意形式の自動変換は未実装である。

`ADC`と`ADC^2`を較正済み`Jy`へ読み替えない。`sqrt(Jy)`の模擬例を未確認の実ADCへ指定しない。clockとsample mapping、RFの位相/rate差も別に確認する。

## 4. 読取・識別・有限処理の記録

| 項目 | 結果・根拠ID |
| --- | --- |
| 入力byteの識別と使用したソフト版 | 未記入 |
| 実際に検査/読取したheader範囲、seekで飛ばした範囲 | 未記入 |
| 必要なguardと要求区間が原本に存在するか | 未記入 |
| 入力/metadataの変化が無いことを確認した境界 | 未記入 |
| 使用したmanifest/clock/rateと出力先 | 未記入 |
| complete / incomplete / 未実行、失敗理由 | 未記入 |
| 物理的に未確認の条件と、次に必要な根拠 | 未記入 |

既存`InputIdentity`は上位Closure pipeline/sequenceのrunでfresh SHAとstat境界、小さいmetadataの再hashを扱う。直接`correlate_aligned`の呼出し自身が同じidentity管理を自動実行するという意味ではない。SHAは全headerや物理量の証明ではなく、全statを保つ改変などの限界もある。同等preflightをこの票のために新設しない。

原本を上書きせず、新しい出力先を使う。完成先や`.partial`をそのまま再利用せず、失敗記録を保持して原因を直し、必要なら別の先へ最初から処理する。これは自動checkpoint再開ではない。3秒/600m等の現在の有限処理制限は[clock規約](../../interfaces/clock-model.md)を確認し、4msの成功や圧縮出力を全夜の容量/速度へ外挿しない。

## 5. 引渡し時の整理

「必要ファイルを用意した」「形式・byteを確認した」「物理的根拠がある」「相関/画像処理を実行した」を別に記入する。未確認がある状態で受け渡す場合も、その状態と不足を隠さない。票を埋めること自体は画像の成功認定でも、新しい実行可否ゲートでもない。

現在の4模擬原本と取得contextの確認は[段階148](../reports/148-real-input-evidence.md)、画像誤差モデルの適用条件は[145](../../interfaces/image-noise-applicability.md)を参照する。
