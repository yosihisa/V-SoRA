# 実観測を処理するための準備

## VDIFだけでは条件が足りない

VDIFは電圧sampleを局識別・時刻等とともに運ぶための標準形式です。ただし、その時刻が実sampleに正しく対応するという証拠や、アンテナ位置・RF設定・較正情報をすべて保存する形式ではありません。

| 必要な情報 | 何に使うか | 現時点での状態 |
| --- | --- | --- |
| sample番号とUTC、測定法、不確かさ | 異なる局で同じ瞬間の電圧を選ぶ | 実機測定が必要。PCのUSB到着時刻だけでは不十分 |
| 公称/実sample rate、適用時間 | 時間とともにずれるsampleを補間する | 短い区間の線形clockモデルを入力できる |
| 局位置、座標系、位置誤差 | 幾何delayとu,v,wを計算 | 現在の例は仮想地点とENU位置 |
| 天体位置、基準座標系 | 位相中心を決める | ICRSの赤経・赤緯を使う |
| RF中心、帯域、I/Q順序・符号 | 周波数と位相の向きを決める | 限定profile。実RTL-SDRの符号は実測確認が必要 |
| bit深度、量子化scale | 記録値から電圧値へ戻す | 8bit complex、4096sample/frameを検証 |
| 欠損・無効区間・収録設定変更 | 不正なsampleを除外 | frame invalidを扱う。frame内の欠落詳細は別情報が必要 |
| 局間のLO差とsample/幾何delay | 積分前に位相回転と時刻を揃える | 未知skyの短pilot rate。sample時計は測定または推定して入力 |
| 露光内で一定の局利得・位相 | 各cellのClosureで消す | 高精度gain較正を要求しない。時間中の変動・非分離誤差は別 |
| bandpass、偏波、主ビーム、感度 | channel差・偏波・絶対fluxを正しく扱う | 実機の測定・較正手順が未完成 |

OCXO/GPSDOの採用と、時刻・sample・位相が実際に揃ったかは別に確認します。現状のソフトは未知の弱い天体から、すべての時計情報を自動復元する完成品ではありません。

## 実観測で目指す処理順

高精度の利得・位相較正を用意できない前提で、**Closure＋RML**を主経路にします。詳しい原理と実装順は[Closureの設計](../design/closure-rml-plan.md)を参照してください。

1. 原本VDIFを保存し、checksum・局・sample数・無効区間を確認する。
2. 実時計と局位置を含むsession manifestを用意し、sampleと幾何delayを整列する。
3. 非常に短いpilot相関で局間周波数差を調べる。未知の天体振幅・位相と、時間方向の位相回転速度を区別する。モデルを使わない短pilot推定を段階022で追加した。現在は3秒以内・一様cadence・連結graph・一定gain/rate等の条件を守る。
4. 周波数差をIQへ戻して補正し、数百ms〜数秒の範囲で再相関する。積分中に失う相関はClosureでは戻らない。
5. 妨害channelを除き、各時刻・各channelでClosure phaseとlog closure amplitudeを作る。局応答が大きく変化する区間や異なるchannelを先に複素平均しない。
6. SNRとClosure間の共分散を使い、非負画像と滑らかさ等の条件を置くRMLで形状を推定する。小規模のRML参照実装を追加した。段階023で短区間VDIFのrate推定とRMLを接続した。別時刻の短露光は「合成画像」で集められる。連続長記録の自動処理は後続段階。
7. 相対flux・位置の基準・使った事前条件・残差・不採用データを結果とともに保存する。

段階020ではADC²またはJyの相関からClosureを取り出せます。Closure値は無次元またはradなので、これ自体はJy較正を必要としません。CLEAN比較経路は引き続きJy入力を要求します。Closureだけでは絶対fluxと位置原点を測れません。外部の値を設定した場合は「仮定した制約」と記録します。

## 容量の例

sample rate2.048MHz、8bit I+8bit Qなら、一局は約4.096MB/sです。4時間で約59GB、8局で約472GBになります。これは計算値です。VDIFヘッダー・作業コピー・バックアップを加えるとさらに増えます。

相関出力も、短い積分・多数channelで長時間保存すると大きくなります。まず短いpilotを処理し、時計と周波数差を合わせます。その後もOCXOの制約に合わせ、数百ms〜数秒の積分を保存します。長時間観測と一回のコヒーレント積分は別です。連続全観測の速度は未測定です。8局1秒の有限CPU参照処理は約19秒・peak RSS約325MiBでした。[測定条件](../reports/026-bounded-fx.md)を確認してください。[容量とPC構成の設計](../design/2026-10-02-operational-architecture.md)に仮定を分けて記載しています。

## 次に実機から欲しい測定

共通の強い試験信号で、I/Qの向き、sample開始差、実sample rate、LOの差、温度による変化、欠損を調べるのが最初の候補です。その後、アンテナ・受信機の感度とRFI環境を測り、Closureに使える基線のSNRと、数百ms〜数秒で残るコヒーレンスを評価します。具体的な試験接続はハードウェアの仕様が判明してから決めます。

実測局位置や装置serialなどはローカルの観測データとして管理し、公開リポジトリへ個人の所在地や識別情報を入れません。公開例は仮想地点とST01などの局IDを使います。


「感度計画」で、有効面積・Tsys・短積分からSNR10のClosure期待数を調べられます。未知gainを消せることと、信号が十分強いことは別です。[感度の概算](08-sensitivity.md)を観測条件の検討に使ってください。
