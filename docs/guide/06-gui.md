# 日本語GUIを使う

## 起動する

WSL上のUbuntuで、リポジトリの最上位から実行します。

```sh
.user-venv/bin/pip install -r requirements/verified-ui-linux.txt
.user-venv/bin/pip install --no-deps -e .
.user-venv/bin/vsora-ui --workspace . --port 8765
```

Windowsのブラウザで `http://localhost:8765` を開きます。WSL上のネットワークアプリへWindowsからlocalhostで接続する使い方は[Microsoftの説明](https://learn.microsoft.com/en-us/windows/wsl/networking)にあります。この環境ではWSL内のChromiumで実操作を確認しました。Windows側のブラウザ画面とWSLgのdesktopは直接確認していません。

開発中のソースを実行する場合は、同じPythonで `python tools/run.py vsora_ui --port 8765` を使えます。サーバーを止めるときは、起動したターミナルでCtrl+Cを押します。

## 模擬観測

1. 最初は点源を選びます。
2. 局数・配置・観測時間・積分時間・flux・SEFDを指定します。
3. 「模擬観測して画像化」を押します。
4. 実行履歴で状態・画像・正解との差を確認します。
5. Cas Aや配置・雑音を変え、別の実行として比較します。

この画面は理想visibilityを直接作る方式です。短いIQからの時計・LO検証は動作検証で扱います。観測時間の入力は地球自転による基線の変化を調べるための条件で、実IQをその時間だけ収録する操作ではありません。

## 動作検証

- 雑音・妨害：周波数ごとのpower変動から連続波・パルスを除外する模擬試験。
- 時計：sample開始差と実sample rateの違いを補間で合わせる試験。
- 位相回転：短いpilotから回転速度を推定し、IQ補正後に再相関する試験。
- 基本動作：小規模な自動回帰をまとめて実行。

検証用workflowはcheckoutに置いてあります。wheelだけを別フォルダで使う場合、基本の模擬観測は使えますが、checkoutのない検証ボタンは無効になります。

## 履歴・中止・保存

一件ずつ処理し、残りは実行待ちになります。履歴から中止できます。サーバーの起動時に前回未完了の記録を見つけた場合、中断として表示します。失敗・中止の途中結果を完了品として使いません。

実行ごとに`outputs/gui/<実行ID>/`を作り、入力条件・状態・ログ・相関ファイル・画像・数値を残します。GUIの「保存」からダウンロードできます。同じデータを再実行すると、新しい実行IDで保存します。ここはGit管理外です。

「処理完了」はプログラムがその処理を完了した意味です。CLEANの収束、誤差、実観測への適用範囲は数値と条件を見て別に判断します。詳しくは[結果の読み方](03-results.md)を参照してください。

## 表示と現在の範囲

日本語フォントを同梱しているため、Ubuntuの日本語フォントがなくても画面の文字を読めます。ブラウザはlocalhostのファイルだけを読み、外部CDNへ依存しません。最初の読込みでフォント約4.35MBを取得します。

現在のGUIは模擬観測・Closure＋RML・検証・VDIF解析・区間列解析・合成画像・感度計画・履歴です。実観測では高精度な局利得較正を前提にせず、短い積分で周波数差を扱った後、Closureを使う経路を検討しています。絶対flux・位置と積分中の相関損失は、Closureだけでは決まらない項目です。

Closureの局誤差不変性と0.3秒の周波数差は「動作検証」から実行できます。CLEANの理想模擬観測の長い積分は、実OCXOの積分能力を表していません。実観測の主経路は数百ms〜数秒とClosure＋RMLです。

「Closure＋RML」では短露光を全時間に分散した模擬復元を実行できます。相対画像・停止状態・登録前後の誤差を確認します。[結果の読み方](07-closure-rml.md)を参照してください。

「VDIF解析」で観測条件と時計JSONを指定できます。短pilot・未知rate・再相関・Closure・相対RMLを5工程で実行します。[入力の規約](../../interfaces/closure-pipeline.md)に現在の3秒以内の制限を記載します。


「合成画像」で別時刻の整列済み短露光を選び、相対画像を作れます。「感度計画」でアンテナ面積・雑音温度を仮定し、一露光で作れるphase/amplitudeの数を見積もれます。[感度の読み方](08-sensitivity.md)も確認してください。

## 同じVDIFの複数短区間を画像化する

1. 「区間列解析」でsession manifestと時計JSONを指定します。
2. 最初の開始時刻、一回の画像積分、区間数を指定します。初期値は0.002秒、0.3秒、3区間です。
3. pilotの刻みと個数で、一回の画像積分全体を覆います。たとえば2msを256個なら0.512秒です。
4. 開始間隔が空欄ならpilot全体の長さに合わせます。間隔を広くすれば、その時刻だけを選べます。pilot同士は重ねません。
5. 実行履歴で工程数、使用露光、局周波数差の図、区間ごとのpilot条件、最終RMLの停止を確認します。

3区間を0.3秒ずつ使う例では、一局の予定画像露光は0.9秒です。最初から最後までの記録時間とは異なります。欠損・flagを除いた実際の露光は「基線の有効露光範囲」で確認します。

局周波数差は基準局との差で、共通の周波数ずれを測った値ではありません。pilot内で一定と仮定し、測った区間の間を補間しません。初期基線差が時間Nyquist内にあることは、装置の仕様や測定で別途確認します。SK判定ができた割合も区間別に表示します。

GUIは2〜32区間を扱います。各pilotは3秒以内で、時計は渡した線形モデルを使います。記録不足などで失敗した場合は、完了した区間数と停止箇所を表示します。途中の相関値は保存されますが、最終画像が完成した扱いにはしません。再実行は新しい履歴になります。現在は途中からの自動再開を行いません。

「処理完了」でもRMLが反復上限に達することがあります。「選択した探索の停止」を確認してください。正しい天体形状かどうかは、事前条件を変えた比較や模擬正解との比較で別に判断します。
