# 日本語GUIを使う

## 起動する

WSL上のUbuntuで、リポジトリの最上位から実行します。

```sh
.user-venv/bin/pip install -r requirements/verified-ui-linux.txt
.user-venv/bin/pip install --no-deps -e .
.user-venv/bin/vsora-ui --workspace . --port 8765
```

Windowsのブラウザで `http://localhost:8765` を開きます。WSL上のネットワークアプリへWindowsからlocalhostで接続する使い方は[Microsoftの説明](https://learn.microsoft.com/en-us/windows/wsl/networking)にあります。この環境ではWSL内のChromiumで実操作を確認しました。Windows側のブラウザ画面とWSLgのdesktopは直接確認していません。

開発中のソースを実行する場合は、同じPythonで `python tools/run.py vsora_ui --port 8765` を使えます。サーバーを止めるときは、起動したターミナルでCtrl+Cを押します。

## 模擬観測

1. 最初は点源を選びます。
2. 局数・配置・観測時間・積分時間・flux・SEFDを指定します。
3. 「模擬観測して画像化」を押します。
4. 実行履歴で状態・画像・正解との差を確認します。
5. Cas Aや配置・雑音を変え、別の実行として比較します。

この画面は理想visibilityを直接作る方式です。短いIQからの時計・LO検証は動作検証で扱います。観測時間の入力は地球自転による基線の変化を調べるための条件で、実IQをその時間だけ収録する操作ではありません。

## 動作検証

- 雑音・妨害：周波数ごとのpower変動から連続波・パルスを除外する模擬試験。
- 時計：sample開始差と実sample rateの違いを補間で合わせる試験。
- 位相回転：短いpilotから回転速度を推定し、IQ補正後に再相関する試験。
- 基本動作：小規模な自動回帰をまとめて実行。

検証用workflowはcheckoutに置いてあります。wheelだけを別フォルダで使う場合、基本の模擬観測は使えますが、checkoutのない検証ボタンは無効になります。

## 履歴・中止・保存

一件ずつ処理し、残りは実行待ちになります。履歴から中止できます。サーバーの起動時に前回未完了の記録を見つけた場合、中断として表示します。失敗・中止の途中結果を完了品として使いません。

実行ごとに`outputs/gui/<実行ID>/`を作り、入力条件・状態・ログ・相関ファイル・画像・数値を残します。GUIの「保存」からダウンロードできます。同じデータを再実行すると、新しい実行IDで保存します。ここはGit管理外です。

「処理完了」はプログラムがその処理を完了した意味です。CLEANの収束、誤差、実観測への適用範囲は数値と条件を見て別に判断します。詳しくは[結果の読み方](03-results.md)を参照してください。

## 表示と現在の範囲

日本語フォントを同梱しているため、Ubuntuの日本語フォントがなくても画面の文字を読めます。ブラウザはlocalhostのファイルだけを読み、外部CDNへ依存しません。最初の読込みでフォント約4.35MBを取得します。

現在のGUIは模擬観測・Closure＋RML・検証・VDIF解析・区間列解析・合成画像・感度計画・履歴です。実観測では高精度な局利得較正を前提にせず、短い積分で周波数差を扱った後、Closureを使う経路を検討しています。絶対flux・位置と積分中の相関損失は、Closureだけでは決まらない項目です。

Closureの局誤差不変性と0.3秒の周波数差は「動作検証」から実行できます。CLEANの理想模擬観測の長い積分は、実OCXOの積分能力を表していません。実観測の主経路は数百ms〜数秒とClosure＋RMLです。

「Closure＋RML」では短露光を全時間に分散した模擬復元を実行できます。相対画像・停止状態・登録前後の誤差を確認します。[結果の読み方](07-closure-rml.md)を参照してください。

「VDIF解析」で観測条件と時計JSONを指定できます。短pilot・未知rate・再相関・Closure・相対RMLを5工程で実行します。[入力の規約](../../interfaces/closure-pipeline.md)に現在の3秒以内の制限を記載します。


「合成画像」で別時刻の整列済み短露光を選び、相対画像を作れます。「感度計画」でアンテナ面積・雑音温度を仮定し、一露光で作れるphase/amplitudeの数を見積もれます。[感度の読み方](08-sensitivity.md)も確認してください。

## 同じVDIFの複数短区間を画像化する

1. 「区間列解析」でsession manifestと時計JSONを指定します。
2. 最初の開始時刻、一回の画像積分、区間数を指定します。初期値は0.002秒、0.3秒、3区間です。
3. pilotの刻みと個数で、一回の画像積分全体を覆います。たとえば2msを256個なら0.512秒です。
4. 開始間隔が空欄ならpilot全体の長さに合わせます。間隔を広くすれば、その時刻だけを選べます。pilot同士は重ねません。
5. 実行履歴で工程数、使用露光、局周波数差の図、区間ごとのpilot条件、最終RMLの停止を確認します。

3区間を0.3秒ずつ使う例では、一局の予定画像露光は0.9秒です。最初から最後までの記録時間とは異なります。欠損・flagを除いた実際の露光は「基線の有効露光範囲」で確認します。

局周波数差は基準局との差で、共通の周波数ずれを測った値ではありません。pilot内で一定と仮定し、測った区間の間を補間しません。初期基線差が時間Nyquist内にあることは、装置の仕様や測定で別途確認します。SK判定ができた割合も区間別に表示します。

GUIは2〜32区間を扱います。各pilotは3秒以内で、時計は渡した線形モデルを使います。記録不足などで失敗した場合は、完了した区間数と停止箇所を表示します。途中の相関値は保存されますが、最終画像が完成した扱いにはしません。再実行は新しい履歴になります。現在は途中からの自動再開を行いません。

「処理完了」でもRMLが反復上限に達することがあります。「選択した探索の停止」を確認してください。正しい天体形状かどうかは、事前条件を変えた比較や模擬正解との比較で別に判断します。

## pilotを分けて周波数差を確認する

「VDIF解析」と「区間列解析」で、pilotを4分割した局周波数差を確認できます。図の丸はpilot全体、×は各部分の推定です。各部分に8回以上の相関が必要です。測れなかった部分があると「未判定」と表示します。

「4分割のrate整合を必須にする」を選ぶと、変動検出・未判定の段階で画像化前に停止します。初期状態では診断を保存し、従来の一定rate補正を続けます。変動を自動で補正する指定ではありません。

「分割rateは整合」は、4部分の平均が雑音の見積りと整合する意味です。高速な位相変動や相関の減衰がないという保証ではありません。表示する6σの境界は近似雑音に基づく診断基準で、誤検出確率は評価していません。[条件と限界](../reports/036-subpilot-rate-diagnostics.md)を確認してください。

## 滑らかな線形rateを選ぶ

「VDIF解析」「区間列解析」の補正モデルで、初期値の一定rateか、時間に比例して変わる滑らかな線形rateを選べます。線形モデルは4部分とも周波数差を測れる場合に使います。部分を短くすると感度が足りなくなる場合があります。

線形モデルを選ぶと、一定rate整合の必須指定を外して無効にします。線形モデル自身の適合確認は必ず行います。結果で局ごとの傾き（Hz/s）、近似誤差σ、モデルχ²を確認します。coherence表示はモデルから計算した値で、実機の相関保持率を測った値ではありません。

線は各pilot内のモデルです。選択しなかった時間を補間したり、欠損した区間を測定した扱いにはしません。変動検出という診断は、補正前に一定rateを疑った結果として残します。画像は選択したモデルでIQ補正した後の相対画像です。[実施範囲](../reports/038-linear-rate-gui-sequence.md)を参照してください。

## 周期位相の動作検証

「動作検証」で「周期位相変動とClosure」を選ぶと、仮定した位相揺れを加えたIQ→VDIFを作り、対照・一定rate・線形rateを比較します。数分と数百MBの保存容量を使う自己完結した模擬検証です。

履歴の「処理完了」は検証の実行が完了した意味です。表にある各相関の完了/未完了を別に見ます。分割rateが整合しても相関が約15%減衰する例を含みます。比率は同じsky/noiseの対照を用意した検証値で、実観測から測定した保持率ではありません。[条件と限界](../reports/039-periodic-phase-coherence.md)を参照してください。

## 推定誤差だけによる条件付きの予測

線形rateの解析結果には「推定誤差だけから計算した条件付き予測」を表示します。「基線ごとの条件付き診断」を開くと、各基線の値と積分両端の位相誤差を確認できます。区間列では「区間ごとの周波数差とpilot条件」を開き、窓ごとの診断を見ます。古い保存結果に診断がない場合は、そのことを表示します。

この値は、保存された誤差共分散が正しく、誤差がGaussian分布に従い、露光が一様だと仮定した計算です。実機の保持率・1回の観測の下限・振幅の平均を示しません。欠損や除外mask、モデル外の速い位相揺れは含みません。値が高くても観測時間や画像品質の安全を保証しません。

「動作検証」の「推定誤差のGaussian計算」では、65,536組の仮定誤差を生成し、数式と乱数標本の複素平均を比較します。振幅の平均も別列に表示します。推定器の共分散や実OCXOを測った実験ではありません。checkoutが必要ですが、大容量VDIFは生成しません。

周期位相検証では、線形rateの条件付き予測約99.98%と、モデル外の揺れによる対照振幅比約84.59%を同じ条件の行で確認できます。計算対象が違うことを区別して読みます。[GUIの実施・検証範囲](../reports/041-rate-uncertainty-gui.md)、[数式と計算検証](../reports/040-linear-rate-uncertainty.md)を参照してください。

## rateの近似誤差σを調べる

「動作検証」の「rate近似σの共分散」を選ぶと、相関値に仮定した雑音を加え、8条件それぞれ1,024回の推定を繰り返します。約1分の計算で、大容量VDIFは生成しません。checkoutの検証workflowが必要です。

表の「採用 / 全試行」は、推定できて採用条件を満たした回数です。残りは未採用で、精度の統計には入りません。「誤差距離 ÷ 6」は、rate3個と傾き3個の誤差を保存共分散に照らして測った値です。正しいGaussian誤差モデルで選別がなければ期待値は1ですが、この表は採用例だけの結果です。

「公称95%領域内（採用例）」は、近似共分散から作った誤差領域へ、採用例の何割が入ったかを示します。95%という設定が実際の観測の保証になるわけではありません。条件によって約79〜100%となる例を含みます。未採用を除いた割合なので、観測全体の成功率とも異なります。

σは仮定した相関値雑音の大きさ、ρは各局の共通点源信号の割合を表すcoherenceです。条件ごとのSNRは揃えていません。実IQ・VDIF、実OCXO、Cas Aの画像品質を測った実験ではありません。結果から実機の誤差へ掛ける補正係数を決めません。[計算条件](../reports/042-rate-covariance-validation.md)、[GUIの検証範囲](../reports/043-rate-covariance-gui.md)を参照してください。

## 共有雑音とClosureの一次近似を調べる

「動作検証」の「Closure共有雑音と一次近似」では、4モデルそれぞれを2つの方法で16,384回生成します。「相関値にGaussian雑音」は、相関値の分布をGaussianに近似した試験です。「Gaussian電圧から相関」は、512個の電圧標本を作って平均相関を計算した試験です。ADC量子化・FIR・VDIFは含みません。

「標本分散 / 一次近似」は、作った標本で測った雑音分散を、微分による一次近似で計算した分散で割った値です。1なら一致します。表は4個のClosure phaseと2個のlog closure amplitudeの最小〜最大を示します。有限試行のばらつきや非線形変換の差は残ります。

「一次近似 / 独立雑音」は、基線間や実部虚部の雑音相関を含めた式と、独立円対称基線雑音の式との違いです。共有点源の特殊な仮定ではρ=0.5なら0.25となりますが、一般の天体や実機の補正係数ではありません。二成分ではphaseとlog amplitudeの交差共分散も計算し、詳しい条件と数値へ保存します。

局の共分散を既知とし、既知の平均SNRで条件を固定した検証です。観測された値による選別はしていません。実受信機の未知の雑音を推定した結果ではなく、現在のRML重みも変更しません。[モデル・式の条件](../reports/044-joint-closure-noise.md)、[GUIの実施範囲](../reports/045-closure-noise-gui.md)を参照してください。


## 保存済み相関の雑音を診断する

1. 「雑音診断」を開きます。完了したVDIF解析・区間列解析の履歴から個別相関ファイルを選ぶか、WSL側のNPZの場所を直接指定します。
2. 「入力の時刻・周波数を読む」を押します。相関に保存された相対時刻とRF周波数から選びます。UTC原点が未保存なら、絶対時刻を確認できた扱いにしません。
3. 「選んだ場所の雑音を診断」を押します。履歴で処理の完了と、科学的な診断の状態を別々に確認します。
4. 「条件付き推定」なら、公称共通FFT数、有効Closure行、基線ごとの条件付きSNR、一次近似σを確認できます。全共分散と入力SHA256は保存JSONへ残します。

「未判定」は情報不足・品質flag・FFT集合の違い等で、この推定の条件を確認できなかった状態です。「無効」は選択した場所に正の基線重みがありません。どちらも診断処理自体は完了します。低SNRの無効Closure行は「未判定」、σは「—」で表示し、保存値0を誤差ゼロと扱いません。

Closure行には冗長な行も含むので、表示数は独立な画像測定数ではありません。FFTの個数を独立標本数と仮定し、Gaussian電圧・一定の局共分散に基づく条件付き計算です。実際のFFT独立性・FIR/補間・量子化・RFI・実機の信頼区間は未確認です。RMLの重み・採否には適用していません。

初期選択は中央channelですが、RF一覧から選び直せます。ファイルの場所を変更すると軸選択を無効にし、読み直しが必要です。読込後に原本が変更された場合、診断はその時点の原本を再確認するので、出力の時刻・RF・SHA256も確認してください。[保存情報の規約](../../interfaces/observation-noise-diagnostic.md)を参照してください。

## FIR・補間によるFFT雑音を調べる

「動作検証」の「FIR・補間とFFT雑音」では、既知のGaussian電圧と固定したフィルター係数の6条件を各8,192回生成します。checkoutの検証workflowが必要です。実受信機の入力を選ぶ画面ではありません。

「理論分散 / 独立FFT近似」は、時刻間の相関を含めた式の分散を、同じ出力局共分散でFFTだけを独立とした式の分散で割った値です。共通係数なら、たとえば公称128FFTでも幅65の例示平均ではモデル換算数が約23.82になります。これは仮定したモデルの計算で、実機で測った独立標本数ではありません。

局別に係数が違う例では、一つの換算数を出しません。表の「全共分散の構造差」は、要素ごとの共分散の差を対応する対角分散の幾何平均で割った絶対値の最大です。対角分散が一致しても、基線間の共分散が違う例を確認できます。MC差は乱数で測った全共分散と理論の差です。

「全要素6SE内」は、この固定モデルで乱数の有限試行のばらつきと整合した意味です。実際のFIR・量子化・時間変化する時計や、画像の信頼区間を保証しません。RMLの重みは変更していません。[モデルの条件](../../interfaces/filtered-visibility-noise.md)、[GUIの検証記録](../reports/050-filtered-noise-gui.md)を確認してください。

## pilot全体の時間方向の散らばりを調べる

1. 「雑音診断」で「pilot全体の時間方向の散らばり」を選びます。
2. 完了した解析・区間列の履歴から`pilot/shard-00000.npz`を選ぶか、保存pilotを直接指定します。32〜8192個の非重複時間cellが必要です。
3. 「入力の時刻・周波数を読む」を押し、RFを選びます。一つの時刻を選ぶ欄は無効になり、そのRFの全時刻を使います。
4. 補正前pilotに一定/線形rateを追加する場合は、同じ観測のprofile JSONを指定します。補正済み相関は空欄にします。局ID・UTC・有効時刻範囲を検証し、二重補正を拒否します。
5. 「時間方向の散らばりを診断」を押します。処理の完了と診断の有効性を分けて読みます。基線ごとの時間power・平均power・差・平均/時間powerの比、JSON保存を確認できます。

両powerから仮定した雑音寄与を引きます。比は振幅保持率と異なり、負や1超の値もそのまま表示します。時間powerが非正なら「未判定（信号power不足）」と「—」を表示します。差には位相・振幅・天体・雑音モデルの変化が混ざります。値だけで実機coherenceや画像品質を判定しません。

追加profileはcell中心の位相回転で、cell内ですでに起きた平均化損失を回復しません。同じpilotで測ったprofileへの依存と、FFT/time cellの独立性・実機信頼区間は未校正です。RMLの重み・採否は変更していません。詳細は[CLI・式・制約](../../interfaces/pilot-time-scatter.md)、[GUI検証](../reports/052-pilot-time-scatter-gui.md)を参照してください。

## 低SNR向け三基線積の雑音偏りを検証する

「動作検証」で「Closure向け三基線積の雑音偏り」を選ぶと、既知Gaussian電圧の5条件を各16,384回生成します。checkoutのworkflowが必要です。実IQ・VDIFを新たに作る検証ではありません。

三基線の相関積（bispectrum）の角度がClosure phaseです。同じ標本から作った三つの相関は雑音を共有し、普通の積に平均偏りが残る場合があります。異なる標本だけを使うU₃の平均と、普通の積の理論偏りを比較できます。

表の真値は検証だけで分かる値です。「6 MC SE内」はこの固定モデルの有限試行の平均が理論と整合する基準で、実機の信頼区間ではありません。非常に弱い信号では、偏りを除いた複素量も今回の試行数で真値を分解できません。U₃の不偏性は角度や振幅、画像品質の保証と異なります。

独立電圧・積分内gain一定という条件が必要で、FIRの標本間相関・実OCXO・ADCは未検証です。現行相関器/RMLの統計・採否は変更していません。[導出と条件](../../interfaces/distinct-sample-bispectrum.md)、[GUIの実施範囲](../reports/054-bispectrum-validation-gui.md)を確認してください。

## 時間相関と三基線積の偏りを比べる

「動作検証」→「時間相関と三基線積・間引き」→「検証を開始」で、白色・長い平均・基準FFTと、各間引きの5条件を実行します。通常積/U₃のモデル平均、U₃の反復平均とMC SE、保持数と間引き間隔を表示します。

全条件で天体の相互相関は0、局間雑音は独立と仮定します。長い平均では異なる標本番号を使っても残留偏りが見えます。白色入力・固定有限係数の入力範囲が重ならない間隔にすると、そのモデルでは時間相関が消えますが、保持数が128から15/26に減ります。基準FFTの極小偏りは今回の試行数では分解できません。実機の独立数を測った結果や、一律の間引き推奨ではありません。JSONと図を保存できます。[式・仮定](../../interfaces/temporal-bispectrum.md)、[GUI検証レポート](../reports/056-temporal-bispectrum-gui.md)。

## 三基線積の雑音と短積分を比べる

「動作検証」→「三基線積の雑音・短積分の仮定比較」→「検証を開始」で、ゼロ源モデルの分散を5条件で検証します。分散比と有限試行誤差、点源を仮定した積分時間・間引き・保持M・一窓の尺度・同条件の反復数を表示します。参考8行の下の「全32仮定条件を表示」を開くと、全てのSEFD/積分/保持間隔を比較できます。

点源の比較は総fluxと全ての基線の相関fluxが1000Jy、64kHz、同じbispectrumと正規化、窓間独立を仮定します。この点源表は天体ありの分散を使用せず、目標尺度5は検出確率を意味しません。Mと1m円形開口のSEFDも仮定で、実機の測定値ではありません。地球回転や拡がったCas Aの弱い相関信号は別に評価が必要です。JSONと図を保存できます。[式・仮定](../../interfaces/bispectrum-sensitivity.md)、[GUI検証レポート](../reports/058-bispectrum-sensitivity-gui.md)。

## 天体信号と三角形間の誤差相関を比べる

「動作検証」→「天体信号と三角形間の誤差相関」→「検証を開始」で、既知Sの5条件×8192試行を比較します。各条件の独立標本数M、同じ局powerのゼロ源分散に対する分散比、実成分間の最大相関、全共分散の比較量を表示します。

三角形の数が増えても、その誤差が独立とは限りません。完全共通信号は全局に同じ電圧を与えた特殊極限です。これらは観測からの雑音推定や実機の感度ではありません。有限標本の共分散からU₃の分布全体をGaussianと判断せず、画像の信頼度や現行RMLの重みには適用していません。JSONには8×8の全共分散と反復計算の標準誤差も残ります。[計算条件](../../interfaces/joint-bispectrum-moments.md)、[GUI検証レポート](../reports/060-joint-bispectrum-gui.md)。
## 再解析用の三次統計を保存する

実データ解析と区間列解析で「再解析用の三次統計も保存する」を選べます。既定では無効です。処理完了後に追加容量、三局共通FFT数、利用できるchannel・三角形数、元相関との照合を確認し、保存ファイル一覧から `raw-bispectrum.npz` と元の `shard-00000.npz` を一緒に取得してください。

保存したraw値の誤差と実FFTの独立性は未確認です。現在の画像は従来のClosureから作っており、追加統計を画像尤度に組み込んだ結果ではありません。

## 保存した三次統計を確認する

1. メニューの「保存三次統計」を開きます。
2. 完了した単一解析・区間列解析の履歴から、追加統計と元相関を組で選びます。履歴がない場合は、WSL側の二つのNPZの場所を直接入力できます。
3. 「二つの入力を照合し時刻・周波数を読む」を押します。元相関が対応するファイルかを確認して、時刻とRFの選択欄を用意します。
4. 確認する時刻とRF周波数を選び、「選んだ三次統計の値を確認」を押します。
5. 実行履歴に、三角形の局ID、三局共通FFT数、状態、U₃と通常の積の実部・虚部が表示されます。全桁の値と入力SHAは `bispectrum-inspection.json` に保存します。

「未計算」は共通FFT数が3未満で、測定したゼロとは異なります。「品質マスクで利用不可」は保存値があっても採用できない状態です。「形式上利用可」は数とflagの条件を満たすだけで、実FFTの独立性や十分な感度を保証しません。FFT数を実際の独立標本数と読み替えないでください。

ファイル名を編集した場合は選択を無効にし、再読込を求めます。同じファイル名でも原本を置き換えた場合は、実行時に識別情報の違いを検出して停止します。対応する二つの保存済みファイルを固定してください。

通常の積は三局共通集合での三辺平均の積です。二局ごとの有効標本が異なる元相関の積とは一致しない場合があります。U₃との差から一回の観測の偏りを推定する機能ではありません。雑音σ、位相の信頼度、検出確率、未知gainの正規化、画像品質は推定せず、現行RMLには適用していません。[入力と結果の規約](../../interfaces/bispectrum-inspection.md)を参照してください。
## 短積分平均の誤差分布を確認する

「動作検証」の「短積分平均と三次統計の誤差分布」を選ぶと、既知の5モデルをそれぞれ8,192回生成し、平均回数Q=1/4/16/64の20条件を比較します。1スレッドの参照環境では約1分かかります。

表の「公称95%領域の実測包含率」は、Gaussianなら95%を含む領域が、今回の三次統計U₃を実際に何%含んだかを表します。公称値と違っても、モデル計算を正常に実行できれば「処理完了」になります。低SNRでの非Gaussianな分布を確認するための実験です。

反復標準誤差は、有限回の模擬実験による数値のばらつきです。図の誤差棒はその2倍です。実機の信頼区間や画像品質を表す値ではありません。距離平均が理論値に近いことだけでGaussian性を判断しないでください。

保存ファイル欄から20条件のJSONを取得できます。実FFTの独立性、時間変化する未知gain、量子化、同じ記録での時計推定は含まず、Qを観測秒数へ換算しません。[平均化の条件](../../interfaces/bispectrum-window-averaging.md)も参照してください。
