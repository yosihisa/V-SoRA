# 現在の開発計画

## 目指す完成形

実際のRTL-SDRが記録したIQと補足情報から、時計補正・相関・較正・画像復元を実行し、条件と結果を保存することです。Windows収録ソフトはハードウェア側の状況に合わせて後で作ります。処理の意味は[入門ガイド](../guide/README.md)を参照してください。

## 到達した段階

| 段階 | 確かめたこと | 残る確認 |
| --- | --- | --- |
| 001～003 | 共通条件、点源の画像化、Cas Aモデルと局配置比較 | 実測感度、現実の観測条件での配置評価 |
| 004～006 | IQ→VDIF→相関→FITS-IDI→画像、CASAの符号・単位 | 他形式・複数偏波・実装置のI/Q向き |
| 007～010 | 受信機の振幅/位相/delay/rate、時計ずれ、処理CLI | 実天体からの時計推定、非線形な時間変化 |
| 011～013 | 独立環境、Cas A形状を使う較正、channel保存、CLEAN修正 | 独立した較正基準と実天体の検証 |
| 014～017 | 短い区間のsample整列、1ms積分、CASA変換、模擬RFI | 長時間処理、bandpass、実機の誤検出率 |
| 018 | 学部生向け文書の整理 | 文書とGUIを開発に合わせて更新 |

各項目の条件・成功・失敗は[段階レポート](../reports/README.md)に保存しています。理想条件の結果と実観測での成功を分けて判断します。

## 次に進める順番

1. 日本語ブラウザGUI：模擬観測・主要検証・収録データの相関/較正/画像化を選び、実行状態と結果を見られるようにする。
2. 長いVDIFを小さい単位で時計補正し、必要な平均時間へまとめる。途中失敗や再実行も記録する。
3. bandpassや雑音の扱いを追加し、受信機応答を変えた模擬データで検証する。
4. 強い共通信号による実機試験、sample時刻・周波数・量子化・連続性の確認。
5. 感度とRFI環境を実測し、Cas A観測の較正手順を選ぶ。
6. 実観測で画像・残差・flux・位置を確認する。その後、必要なGPU処理や既製相関器との比較へ進む。

現在はCPUによる参照実装です。GPU搭載機でも自動的にGPUへ移る構造ではありません。正しさと処理時間を測ってから、重い処理にGPUを導入します。
