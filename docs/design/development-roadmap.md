# 現在の開発計画

## 目指す完成形

実際のRTL-SDRが記録したIQと補足情報から、時計と局別周波数差を補正し、数百ms〜数秒の相関を保存してClosure＋RMLでCas Aの相対画像を求めることです。周波数は1.42GHz、最大基線は約600m、精密な局gain較正が困難な条件を維持します。Windows収録ソフトはハードウェアの進捗に合わせて開発します。

## 次に進める順番

1. **低SNRでの形状識別を先に評価する。** 既知モデルのU₃尺度だけでは画像の成功を判定できない。未知gain、天体自己雑音、時間/周波数相関を含む有限電圧で、点源等とCas Aを区別する評価を定義する。
2. **未知の周波数差と補正を同じ条件へ接続する。** 短pilotの採用・失敗、補正後の相関保持、速い位相変動の見逃しを記録する。真値の逆位相を与えた検証と区別する。
3. **確認できた誤差モデルを画像化へ接続する。** 現在の高SNR phase/logamp近似を使える条件を示し、弱い信号用の尤度・不確かさを検証する。生成形状を事前画像として入力せず、探索停止・初期値・残差・位置の自由度を評価する。
4. **実機入力の契約を測定値で確定する。** I/Qの向き、sample/UTC、sample rate、局別周波数、欠損、感度・RFIを測り、原本と補足情報を同じ解析へ渡す。
5. **実観測全体の運用と性能を測る。** 有限window列から全夜の再開・容量・速度を確認する。CPU実績からGPUへ移す対象を選ぶ。

局gainの既知モデル較正は比較経路として残っています。Closureの局誤差不変性だけでは積分中の位相回転を戻せません。母平均・誤差尺度・検出確率・画像品質を別の判断として記録します。[設計と条件](closure-rml-plan.md)を参照してください。

現在はCPUによる参照実装です。GPU搭載機でも自動的にGPUへ移る構造ではありません。実機・低SNR統計・全夜運用の確認が済むまでは、ソフト全体の完成や実観測での復元成功とは扱いません。
