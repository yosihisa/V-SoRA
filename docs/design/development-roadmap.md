# 現在の開発計画

## 目指す完成形

実際のRTL-SDRが記録したIQと補足情報から、時計と局別周波数差を補正し、数百ms〜数秒の相関を保存してClosure＋RMLでCas Aの相対画像を求めることです。周波数は1.42GHz、最大基線は約600m、精密な局gain較正が困難な条件を維持します。Windows収録ソフトはハードウェアの進捗に合わせて開発します。

## 次に進める順番

[118](../reports/118-multitime-vdif-controls.md)は通常LO推定・真値LO・理想モデルの8時刻画像を比較し、[119](../reports/119-fixed-field-image-grids.md)では格子を粗くすると数値収束する例を確認した。しかし実観測の良好な形を確認した結果ではない。未知LOだけの改良、反復数だけの増加、真値を見た格子選択に絞らず、次の作業を主経路への寄与で選ぶ。

| 次の段階候補 | 目的と受入条件 |
| --- | --- |
| 121〜122：主画像結果の日本語GUI、独立RMLの準備 | GUIは処理/数値/参照を別表示し、参照なし・未収束・不足を成功へ丸めない。source/導入済み実ブラウザ・日本語/390px/全JSONを照合する。外部法は版と依存を別環境へ固定し、点源/二点源のFourier符号・単位・sigma・Closure・w項を先に確認する |
| 123：既製RMLとの同一入力比較 | 118/119と同じ配列で実行し、truthを初期化や閾値選択へ渡さず、同じ形状指標と115のデータ適合を比較。異なる総Fの順位付けをしない |
| 124：格子・正則化の独立評価 | 事前固定の候補と学習/評価の共有範囲を明記。真値を使って選択した値を未知データ性能としない。失敗・未収束も保存し、既定値を変える根拠を示す |
| 125〜126：弱い画像データの誤差と保存量 | 高SNR Closure不足時の最低仕様を定義し、既知条件の小画像で独立計算と比較。全局共通Sが必要なら実共通標本から保存し、三角形の別標本から捏造しない。U₃/p値をそのまま画像尤度へ変換しない |
| 127〜128：短積分・未知LOとの接続 | 同じ原本で.3/1/3秒や変動条件を比較し、既知の真値対照と未知推定を分ける。実OCXOの安定時間を仮定で決めず、採用・失敗・画像までの到達を記録する |

番号は仮計画で、結果・残量・必要な分割に応じて選び直す。小さい段階を増やすこと自体を目的にしない。外部候補の[EHT-imaging](https://github.com/achael/eht-imaging)は以前の調査から再確認したが、119時点で今回の比較用導入・実行は未実施。旧仮説分類GUI草稿は保留のまま、番号だけ変えて適用しない。

実機のI/Q、sample/UTC、実sample rate、LO変動、感度、RFI、欠損を測れる場合は、結果を早期にモデルへ戻す。Windows収録は装置に合わせて後で開発する。CPU/GPUの性能比較は、実データ量と重い工程を測ってから選ぶ。

局gainの既知モデル較正は比較経路として残っています。Closureの局誤差不変性だけでは積分中の位相回転を戻せません。母平均・誤差尺度・検出確率・画像品質を別の判断として記録します。[設計と条件](closure-rml-plan.md)を参照してください。

現在はCPUによる参照実装です。GPU搭載機でも自動的にGPUへ移る構造ではありません。実機・低SNR統計・全夜運用の確認が済むまでは、ソフト全体の完成や実観測での復元成功とは扱いません。
