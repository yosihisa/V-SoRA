# 現在の開発計画

## 目指す完成形

実際のRTL-SDRが記録したIQと補足情報から、時計と局別周波数差を補正し、数百ms〜数秒の相関を保存してClosure＋RMLでCas Aの相対画像を求めることです。周波数は1.42GHz、最大基線は約600m、精密な局gain較正が困難な条件を維持します。Windows収録ソフトはハードウェアの進捗に合わせて開発します。

## 次に進める順番

[109の主画像経路](../reports/109-image-path-acceptance.md)では、同じ弱い原本の1秒pilotがLO推定で停止した。最終積分だけ延ばしても上流の情報は増えない。高感度側も画像を保存したが最適化は未収束だった。この結果から、次の順番へ具体化する。

| 次の段階・課題 | 目的と完了条件 |
| --- | --- |
| 111：未知LO取得の対照実験 | 同じ弱い原本でpilot長・利用基線・検出条件を切り分け、採用/失敗・誤検出・補正後相関を保存する。必要なら長さ違いの原本を同じ生成条件で作る。真値補正は評価用対照と明示する |
| 112：結果に基づく補正方針 | 111で確認した範囲で採用条件・探索/補正方法・追加の保存量を選ぶ。強制成功、真値依存、失敗例の除外による改善を避ける |
| 113〜114：画像側の律速 | 未収束、初期値、単一時刻とuv合成、未知振幅/SEFD、低SNR誤差を分ける。検証済み誤差モデルを主画像経路へ接続する最小仕様を選び、真値なしで推定した画像を評価する |
| 115前後：必要な日本語GUI | 主経路で必要になった採用/失敗・収束・画像差の情報を観測者へ伝える。既知二候補GUIだけの増加を優先しない |
| 120：定期文書整理 | 時系列・目標別進捗・計画・入口・索引を同じ基準へそろえる |

段階番号は仮計画で、111以降の技術内容は結果に応じて縮小・分割・変更する。実機のI/Q、sample/UTC、実sample rate、LO変動、感度、RFI、欠損を測れる段階では測定値を早期にモデルへ戻す。全夜の再開・容量・処理時間は別に実行して測り、CPUの重い工程を確認してからGPU化を選ぶ。

局gainの既知モデル較正は比較経路として残っています。Closureの局誤差不変性だけでは積分中の位相回転を戻せません。母平均・誤差尺度・検出確率・画像品質を別の判断として記録します。[設計と条件](closure-rml-plan.md)を参照してください。

現在はCPUによる参照実装です。GPU搭載機でも自動的にGPUへ移る構造ではありません。実機・低SNR統計・全夜運用の確認が済むまでは、ソフト全体の完成や実観測での復元成功とは扱いません。
